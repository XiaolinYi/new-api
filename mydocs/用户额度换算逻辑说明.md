# 用户额度（Quota）换算逻辑说明

> 适用场景：管理员在 Web 控制台「用户管理」中调整某用户剩余额度（添加 / 扣减 / 覆盖）时，前端输入金额与实际发送给后端 `/api/user/manage` 接口的 `value` 之间的换算关系。

## 一、结论速览

- 后端接口 `POST /api/user/manage`（`action: add_quota`）收到的 `value` 是**系统内部的整数「额度单位」**，不是管理员输入的 CNY / USD 金额。
- 系统约定：**500,000 额度单位 = 1 USD**（默认 `quotaPerUnit = 500000`）。
- 「显示货币 ↔ 内部额度单位」的双向换算**全部在前端完成**，后端只处理整数单位，不做任何汇率换算。

### 典型例子

管理员选择「添加」、输入 `10`（CNY），系统汇率 `usdExchangeRate = 7.3`（即 1 USD = 7.3 CNY）：

| 步骤 | 计算 | 结果 |
| --- | --- | --- |
| 输入金额（CNY） | — | `10` |
| CNY → USD | `10 ÷ 7.3` | `1.369863…` |
| USD → 额度单位 | `× 500000` | `684931.5068…` |
| 取整 | `Math.round(...)` | **`684932`** |

实际发出的 payload：

```json
{
  "id": 2,
  "action": "add_quota",
  "mode": "add",
  "value": 684932
}
```

`684932` 正是 `10 ÷ 7.3 × 500000` 四舍五入的结果，属于**预期行为，非 Bug**。

## 二、前端换算链路（写入方向）

### 1. 弹窗收集输入

文件：`web/src/features/users/components/user-quota-dialog.tsx`

关键代码（约 L53–L54、L79–L86）：

```ts
const amountValue = Number.parseFloat(amount) || 0          // 管理员输入的金额，按当前显示货币解读
const quotaValue = parseQuotaFromDollars(Math.abs(amountValue))

// 提交时
const value = mode === 'override' ? parseQuotaFromDollars(amountValue) : quotaValue
const result = await adjustUserQuota({
  id: props.userId,
  action: 'add_quota',
  mode,
  value: mode === 'override' ? value : Math.abs(value),
})
```

要点：
- 输入框旁的单位标签取自 `getCurrencyLabel()`（CNY / USD / Tokens / 自定义符号），所以管理员输入的 `10` 会被当作 **10 CNY**（当 `quotaDisplayType = CNY` 时）。
- 非 override 模式统一取 `Math.abs`，保证 `add` / `subtract` 传正值，由 `mode` 决定加减方向。

### 2. 核心换算函数 `parseQuotaFromDollars`

文件：`web/src/lib/format.ts`（L100–L116）

```ts
export function parseQuotaFromDollars(amount: number): number {
  if (!Number.isFinite(amount)) return 0

  const { config, meta } = getCurrencyDisplay()

  // Tokens-only 或原始额度模式：直接四舍五入为整数
  if (meta.kind === 'tokens') {
    return Math.round(amount)
  }

  const exchangeRate =
    meta.kind === 'currency' || meta.kind === 'custom' ? meta.exchangeRate : 1

  const usdAmount = exchangeRate > 0 ? amount / exchangeRate : amount

  return Math.round(usdAmount * config.quotaPerUnit)
}
```

换算公式（货币模式）：

```
value = round( 输入金额 ÷ 汇率 × quotaPerUnit )
```

其中：
- `汇率` = `usdExchangeRate`（CNY 模式）或 `customCurrencyExchangeRate`（CUSTOM 模式）；USD 模式为 `1`。
- `quotaPerUnit` = 每 1 USD 对应的额度单位数，默认 `500000`。

### 3. 汇率与单位的来源

文件：`web/src/lib/currency.ts` + `web/src/stores/system-config-store.ts`

`getDisplayMeta`（`currency.ts` L187–L216）根据 `quotaDisplayType` 决定 `meta.kind` 和使用哪个汇率：

| quotaDisplayType | meta.kind | 符号 | 使用的汇率 |
| --- | --- | --- | --- |
| `USD` | `currency` | `$` | 固定 `1` |
| `CNY` | `currency` | `¥` | `config.usdExchangeRate` |
| `CUSTOM` | `custom` | 自定义符号 | `config.customCurrencyExchangeRate` |
| `TOKENS` | `tokens` | — | 不换算（`quotaPerUnit` 即每 USD 的 token 数） |

默认配置（`system-config-store.ts` L50–L57）：

```ts
export const DEFAULT_CURRENCY_CONFIG: CurrencyConfig = {
  displayInCurrency: true,
  quotaDisplayType: 'USD',
  quotaPerUnit: 500000,
  usdExchangeRate: 1,
  customCurrencySymbol: '¤',
  customCurrencyExchangeRate: 1,
}
```

> 这些值来自后台「系统设置 → 计费」，前端通过 `useSystemConfigStore` 实时读取，因此修改汇率后前端换算会立即变化。

## 三、前端反向换算（展示方向）

额度加完后，用户 `Quota` 字段存的是 `684932`（内部单位）。页面展示时走反向换算：

文件：`web/src/lib/currency.ts`，`formatQuotaWithCurrency`（L516–L525）

```ts
export function formatQuotaWithCurrency(quota, options) {
  const { config } = getCurrencyDisplay()
  const amountUSD = quota / config.quotaPerUnit   // 684932 ÷ 500000 = 1.369864 USD
  return formatCurrencyFromUSD(amountUSD, options) // 1.369864 × 7.3 = 10.0000… CNY → 显示 ¥10
}
```

`formatCurrencyFromUSD`（L408–L439）中：

```ts
const value = amountUSD * meta.exchangeRate   // USD × 汇率 = 显示货币金额
```

于是 `684932` 单位在 CNY 模式下显示为 **¥10**，与管理员输入一致，形成自洽闭环。

## 四、后端行为

文件：`controller/user_quota.go`（L13–L82）

```go
func manageUserQuota(c *gin.Context, req ManageRequest) {
    // ...
    adjustment, err := model.AdjustUserQuota(req.Id, c.GetInt("role"), req.Mode, req.Value)
    // ...
}
```

要点：
- 后端把 `req.Value` **原样**当作整数额度单位传给 `model.AdjustUserQuota`，**不做汇率换算、不做货币解析**。
- 因此前端必须保证发送的是已换算好的内部单位；后端只校验 `mode` 合法性、`value > 0`（add/subtract）、权限、钱包上限等。
- 审计日志中记录的 `requested_quota` / `quota` 也都是这个内部单位值。

测试佐证（`controller/user_manage_test.go`）：用 `value: 500` 调用 add，断言 `user.Quota` 从 `1000` 变为 `1500`，证明后端是在内部单位上直接做整数加减。

## 五、设计动机

1. **统一内部单位，避免浮点误差**：后端全程用整数额度单位记账，杜绝货币浮点累加误差；汇率换算只在展示层发生。
2. **显示货币可切换**：管理员可把 `quotaDisplayType` 在 USD / CNY / CUSTOM / TOKENS 间切换，数据库里存的额度单位不变，只改前端的展示与输入换算。
3. **后端无状态化**：后端不感知当前显示货币和汇率，换汇策略集中在前端（以及后台配置），便于多端一致。

## 六、注意事项与边界

1. **舍入误差**：最终 `Math.round` 到整数单位。极小金额（如 0.0001 CNY 量级）可能被舍入为 0，导致 `add` 因 `value <= 0` 被前端拦截（`user-quota-dialog.tsx` L75）。这是固定精度的固有取舍。
2. **汇率方向**：`usdExchangeRate` 表示 **1 USD = ? CNY**（如 7.3）。换算时是 `金额 ÷ 汇率` 得 USD，再 `× quotaPerUnit` 得单位。若误以为 `金额 × 汇率`，数值会差一个平方量级。
3. **TOKENS 模式**：当 `quotaDisplayType = TOKENS` 时，`meta.kind === 'tokens'`，`parseQuotaFromDollars` 直接 `Math.round(amount)`，输入即单位数，不经过汇率。
4. **排错清单**：若发现 `value` 与预期不符，依次核对后台配置：
   - `quotaDisplayType`（决定 `meta.kind` 与所用汇率）
   - `usdExchangeRate` / `customCurrencyExchangeRate`（汇率值）
   - `quotaPerUnit`（每 USD 单位数，默认 500000）
   - 前端 `system-config-store` 是否已拉到最新配置（刷新页面即可重新拉取）。
